# Фронтенд авторизации, тесты и совместный запуск

## Интерфейс

Английские страницы `/login`, `/register`, защищённый `/dashboard` с email и Sign out. Корень ведёт в кабинет, гость — на вход. Регистрация проверяет подтверждение пароля только на клиенте. Формы имеют валидацию, показ пароля, состояния ошибок/загрузки и защиту от повторной отправки. Светлая и тёмная темы используют CSS Modules и переменные; системный выбор по умолчанию, ручной — в отдельной cookie без вспышки темы. Адаптивность, клавиатура, autocomplete, доступные подписи и ошибки обязательны. Мониторинг и восстановление пароля исключены.

## Сессия

Next.js Route Handlers `POST /api/auth/{register,login,session,logout}` обращаются к Go. JWT и refresh остаются в HttpOnly cookie `uptime_access` (Path=/, 15 минут) и `uptime_refresh` (Path=/api/auth, исходный срок Go). SameSite=Lax, без Domain, Secure в production. Токены не возвращаются браузеру через JSON, props или Web Storage. Go получает Bearer и refresh_token. BACKEND_URL и APP_ORIGIN — серверная конфигурация. Origin и X-CSRF-Protection проверяются, кэш отключён.

Session вызывает /me; при отсутствующем access или 401 выполняет один refresh и один повтор. Невалидный refresh очищает cookie; сеть/5xx оставляют сессию для повторной попытки. Персональные данные скрыты до проверки. Проверка при загрузке и возвращении во вкладку; без refresh в SSR/prefetch. Web Locks сериализуют auth между вкладками, одновременные проверки одной вкладки объединяются; BroadcastChannel несёт только события. Без Web Locks показывается сообщение об обновлении браузера. Logout требует подтверждения Go.

## Общий запуск

`node scripts/dev.mjs`: проверить инструменты, Docker, зависимости, env и порты; поднять Compose; применить миграции; собрать и запустить Go; дождаться 401 /me; запустить Next.js и проверить готовность. Локальные файлы не перезаписываются, process env имеет приоритет. Backend-секреты не передаются Next.js. Префиксы логов, таймауты, остановка обоих деревьев процессов по сигналу/сбою. PostgreSQL и volume остаются. Чужие процессы не останавливаются. Go перезапускается вручную, Next.js поддерживает HMR. Порты 3000/8080, БД из конфигурации.

## Тесты

Vitest: Node для серверной логики, jsdom + Testing Library/user-event/jest-dom для компонентов, V8 coverage без численного порога. Проверить cookie, JWT/refresh, CSRF, ошибки, дедупликацию, уведомления, формы, темы и кабинет. Тестировать общий запуск с подменой процессов.

Playwright Chromium desktop/mobile: настоящий Go и отдельная PostgreSQL `uptime_e2e_test`, порты 3001/8081, уникальные аккаунты, подготовка миграций и cleanup своих процессов. Проверить полный вход/выход, ошибки, reload, refresh после удаления access, две вкладки, недоступность сервиса, HttpOnly, отсутствие утечек, темы и клавиатуру. Trace/screenshots при сбое; артефакты не коммитить.

Команды: npm test, test:watch, test:coverage, test:e2e, test:e2e:ui. Итоговые проверки: lint, build, Vitest, Playwright и реальный общий запуск/остановка.

## Результаты проверок

- Vitest: 40 тестов пройдено.
- Playwright: 12 сценариев desktop/mobile пройдено с настоящим Go API и PostgreSQL `uptime_e2e_test`.
- Общий скрипт поднял оба сервиса для E2E и освободил порты 3001/8081 после завершения. PostgreSQL сохранён.
- Общий launcher и актуальный Vitest требуют Node.js 22.12+; локально проверяется Node.js 24.19.0.
- ESLint и production-сборка прошли. V8 coverage: 94.32% statements, 87.37% branches, 98.14% lines для frontend auth/theme.
- Скриншоты светлой/тёмной темы и мобильной регистрации просмотрены; горизонтального переполнения нет.
- После намеренного завершения тестового Go-процесса launcher остановил Next.js, завершился с кодом 1 и освободил оба порта.
